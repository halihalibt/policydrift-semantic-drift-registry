# Independent validation

Two distinct `gl.vm.run_nondet_unsafe` consensuses run during registration: target-validity classification and initial source extraction. A drift check runs the source extraction consensus against a copied immutable Baseline snapshot. During source extraction, `leader_fn` and `validator_fn` each call `gl.nondet.web.get` independently on the same registered URL and independently call `gl.nondet.exec_prompt` for an OK source. For an unavailable/oversize source they agree on a rigid sentinel payload without asking an LLM.

Every leader and validator payload is parsed against an exact schema and strict enums and lengths. For initial Baselines the exact CCV is `(source_status, presence, disposition)`; for checks it adds the four ordered SDV relations. On a definite `NOT_STATED ↔ PRESENT` transition with source `OK`, all globally known **non-AMBIGUOUS** relations are first canonicalized to `NOT_APPLICABLE` for both leader and validator; their seven-field **canonical** CCVs are then compared exactly. An `AMBIGUOUS` relation is never normalized. Other paths retain the original field-specific SDV validation and seven-field exact comparison. Unknown relation strings and malformed structure always fail closed. The validator normalizes the leader's positive quote and searches its independently obtained text. Semantic field text may be phrased differently; where it differs, a separate constrained validator-side JSON classifier must produce four strict `true` booleans. Leader, validator, source and target are explicitly untrusted data. The classifier cannot choose final verdict or flags. Malformed JSON, unmatched quote, CCV disagreement, false equivalence, or validator exception causes rejection. Storage writes occur only after consensus returns.

Tests under `tests/` provide deterministic host simulation; the Studio deployment and full-consensus transaction proofs independently verify the actual runtime. Local mocks alone cannot prove LLM/model agreement or real Web Access behavior.
